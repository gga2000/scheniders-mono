## New observations (not in any prior audit)
1. **Any tenant member can rewrite their own tenant's billing/lifecycle columns through REST (HIGH; Confirmed P0 by the Phase 1 critic, now table row NEW-P1-02).** Evidence:
   - SQL: policy `tenants.tenant_member_update` is `USING/WITH CHECK id IN get_user_tenant_ids()` for authenticated, with no role check.
   - Authenticated has column UPDATE on all 25 `tenants` columns (`information_schema.column_privileges`, re-queried in Phase 1 round 1): `address`, `branding`, `business_name`, `city`, `config_version`, `contact_email`, `contact_phone`, `created_at`, `display_id`, `id`, `is_prospect`, `metadata`, `plan`, `prospect_lead_id`, `restrictions`, `settings`, `slug`, `status`, `store_config`, `store_config_draft`, `store_config_rev`, `store_config_v2`, `store_config_v2_draft`, `trial_ends_at`, `updated_at`.
   - The only BEFORE UPDATE trigger (`enforce_storefront_writes_block`) checks branding/store_config only.

   Consequence: a self-signup or employee could PATCH `/rest/v1/tenants?id=eq.<own>` to set `plan`, extend `trial_ends_at`, clear `restrictions` or flip `status`. That bypasses billing, the trial-suspend cron and admin pauses. This is the same "self-serve = admin" pattern as SEC-A and was missed by #119/#146. Not exercised (read-only audit).
2. **Live DDL applied during this audit with no file on main.** `20261019012123_products_brand_size_display_name` (ALTER TABLE products ADD brand/size_ml/display_name) appeared between two queries at about 01:19Z → 01:25Z on 2026-10-19. `20261019010921_activity_logs_append_only` is also live with no file in `migrations/` or `live-history/`. This is REL-B still happening in real time.
3. **WhatsApp bot history writes have no tenant.** `lib/whatsapp-dispatcher.ts:174-180` and `app/api/webhooks/interakt/route.ts:282` omit `tenant_id`, which produced 38 new NULL-tenant history rows since 10-11 (all `whatsapp_bot`). These rows are invisible under RLS. This is the active source behind INT-1's NULL-tenant count.
4. **Webhook auth is staged but every enforce flag is unset in prod.** `lib/webhook-auth.ts:173` defaults to monitor. LIGHTFUNNELS_WEBHOOK_SECRET and INTERAKT_WEBHOOK_SECRET exist in env, so flipping `WEBHOOK_AUTH_MODE=enforce` is a no-code change. It is blocked only by confirming that the real senders present a credential.
5. **`auto-no-response` server cron is not scheduled.** `app/api/cron/auto-no-response/route.ts` exists, but `apps/platform/vercel.json` does not list it, so the browser rule (`use-orders-query.ts:187`) is the only enforcer (feeds WA-1).
6. **anon still holds write + TRUNCATE on several ledgers.** These are `wallet_transactions`, `inventory_ledger`, `order_deletion_log` and `order_status_history`. RLS blocks DML, but TRUNCATE ignores RLS. The risk is latent (PostgREST exposes no TRUNCATE), but it should be revoked with INT-2.
