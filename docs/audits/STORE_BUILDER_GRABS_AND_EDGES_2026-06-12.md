# Store Builder — SOTA "Grabs" + Edge-Case Sweep (2026-06-12)

16-agent sweep (8 competitor lenses + 8 edge-case lenses, grounded in live code) → 210 raw findings, deduped + prioritized below. Benchmarks: Shopify OS2.0/Magic/Flow, Framer, Webflow, Wix Studio, Builder.io, Plasmic, Webstudio, Replo, Shogun, Intelligems, Hostinger/Hocoos/Durable AI, Klaviyo, Figma/Notion. Tuned for the Iraq COD market.

> Excludes everything already shipped this session (E1 SEO, N3 redirects, E4 foundation, health checks, inspector C2/C7/C12, save/state hardening, Preview modal) and the tracked known-broken defects.

## Headline
Breadth is strong, but three areas have **clustered P0 holes**: (1) the **Iraq-COD money path** (oversell, displayed-vs-charged total, no dedup), (2) the **trilingual promise** (Kurdish renders English, no per-visitor locale, no Arabic fonts, defaults to English), and (3) the **publish/merchant-content security surface** (publish RPC bypasses the patch allowlist + no role check; stored XSS; open redirect; html_embed on checkout). The biggest **feature grabs** are AI generation and the commerce/growth suite (discounts, shipping zones, pixels+CAPI, reviews, bundles/upsells, WhatsApp automation).

# PART 1 — EDGE CASES (fix-first; all grounded in code)

## P0 — data loss / crash / security / money
- **EC1 — Unlimited oversell.** Storefront orders insert `status:'new'`, which the inventory model treats as CLOSED → reserves zero stock; checkout never re-checks stock. Two shoppers race the last unit, both succeed. `checkout.ts:188`, `20260530100000_inventory_reserve_model.sql`, `pdp_buy_box.tsx:168`.
  - **STATUS: DEFERRED (XL / live-data blast radius).** The real fix is to make `'new'` a RESERVED phase so placed-but-unconfirmed storefront orders hold stock. That is a 3-part change, each needing live inspection/QA I can't do headlessly: (1) **inventory-tracking semantics** — there is no `track_inventory` flag; `stock_quantity=0` is ambiguous (untracked vs sold-out). The PDP already treats `stock-reserved <= 0` as OOS, implying "stock is always maintained," but a hard *server* block needs that contract confirmed (or a flag added) or it could reject legit COD orders. (2) **`inv_phase` + `recompute_inventory`** must add `'new'` to RESERVED — but a live audit of existing `'new'` orders is required first (a recompute would suddenly reserve every historical `'new'` order and could flip many products to OOS overnight). (3) **`create_order_atomic`** gains an availability check under its existing `pg_advisory_xact_lock` (rejects when `stock_quantity - reserved_quantity < qty`), which only closes the race *after* (2) makes `'new'` reserve. Ship as one focused, live-QA'd step — same posture as BUG1/BUG25.
- **EC2 — Displayed total ≠ recorded total. ✅ FIXED (Round 9, 2026-06-13).** Was: CTA shows subtotal + 5,000 delivery; the order persists `delivery_fee=0`, `price=subtotal`; courier collects a different amount than recorded → COD reconciliation gap. Fix: new shared `computeDeliveryFee` (single source of truth) — `checkout.ts` recomputes the fee server-side from the verified subtotal and records `delivery_fee` (so `price + delivery_fee` = the displayed/collected total); the cart, checkout-summary, and checkout-CTA sections all consume the same helper (also fixed a pre-existing 50K-vs-75K threshold drift in `checkout_order_summary`). `checkout_form.tsx:92`, `checkout.ts:170`.
- **EC3 — publish RPC bypasses M1 + has no role check.** `publish_store_config_v2` has none of the patch allowlist's guards — any active member (incl. a "viewer") can publish arbitrary unknown roots, a 50MB jsonb (DoS), malicious custom_css/redirects/html. `20260610120000_…diff_summary.sql`.
- **EC4 — Stored XSS on a public page.** `about.body` rendered raw via `dangerouslySetInnerHTML`; merchant-authored config → arbitrary JS on the storefront origin, can skim COD checkout input. `about/page.tsx:61`.
- **EC5 — Open redirect.** A redirect rule `to: https://evil.com` (or `//evil.com`) 308s any matching path off-domain → phishing on a trusted domain. `lib/redirects.ts:22`.
- **EC6 — html_embed XSS on the conversion path.** Sandbox `allow-scripts allow-same-origin` + `valid_on` includes cart/checkout → embedded JS reads parent localStorage/cookies. `html_embed.tsx:80`.
- **EC7 — Malformed config crashes the public store.** No root schema validation; `pages` set non-array → `pages.find` throws in `generateMetadata` (not boundary-wrapped) → hard 500. One member can brick the store. `storefront-runtime.ts:8`, `tenant.ts:36`.
- **EC8 — In-flight PATCH resurrects a discarded draft. ✅ FIXED (Round 9, 2026-06-13).** Was: edit (PATCH in flight) → Revert/Publish nulls the draft → the late PATCH `COALESCE(draft,published)` re-creates a dirty draft with one stale field. Fix (client serialization): the hook tracks the in-flight field PATCH in `inFlightPatchRef`; `publish` and `revert_to_published` now `await` it before mutating the draft, so the patch lands first and the null/publish deterministically wins. (Full server-side optimistic concurrency = BUG25, separately deferred — needs the patch RPC to return its new `updated_at`.) `use-store-builder-v2.ts` revert/publish + `patch_path_allowlist.sql:55`.
- **EC9 — First edit on a never-published store corrupts the skeleton.** Both columns NULL → `jsonb_set` into `'{}'` writes only the patched branch (no schema_version/pages array), array-vs-object divergence; full-save is suppressed for patches → nothing reconciles → lose everything on reload. `patchField` + `route.ts:171`.
- **EC10 — One throwing section white-screens the whole page.** No per-section error boundary anywhere; a throw propagates to route `error.tsx` and replaces header+footer+every section. `RenderSection.tsx`.
- **EC11 — Empty/all-hidden home silently shows the OLD legacy template (or a blank body).** No publish gate; `pickV2Page` returns null on 0 sections → legacy fallback; all-hidden → blank. `storefront-runtime.ts:11`, `health-rules.ts:515`.

## P1 — broken UX / wrong output / integrity
- **EC12 — Kurdish storefront renders English. ✅ FIXED (Round 15, 2026-06-15).** All 69 `locale === "ar" ? AR : EN` chrome ternaries across 30 sections were flipped to `locale !== "en" ? AR : EN`, so Kurdish now falls to the **Arabic** chrome (Iraqi Kurds read Arabic) instead of English; ar/en behaviour is unchanged. Safe because every `=== "ar"` usage is a two-branch Arabic/English string selector (no rtl/dir logic — the app is LTR-only). True Kurdish chrome strings would need a translator (none exist in code) — `ku→ar` is the correct Iraq-market fallback meanwhile; the optional path to real Kurdish is noted. (Cart, Subtotal, Delivery, Promo, steps, Governorate…)
- **EC13 — Storefront is effectively mono-locale. ✅ FIXED body locale (Round 14, 2026-06-14).** New shared `resolveVisitorLocale` (cookie → Accept-Language → default → first-enabled, constrained to `enabled_locales`). `V2Page` resolves the visitor locale (every storefront page funnels through it) and overrides `enrichedRuntime.locale`, so enabled en/ku content is now reachable + an English browser auto-gets English. A `<LocaleSwitcher>` (sets `sb_locale` cookie + reload) is mounted in the tenant layout for multi-locale stores; `<html lang>` now reflects the resolved locale. NOTE: page **metadata** (`generateMetadata`) still uses `default_locale` (canonical for SEO) — per-visitor meta locale is a follow-up. `storefront-runtime.ts:49`, `v2-page.tsx:41`.
- **EC14 — Brand fonts have no Arabic/Kurdish glyphs. ✅ FIXED (Round 13, 2026-06-14).** The Latin brand faces (Bricolage/DM Sans) carry no Arabic glyphs, so ar/ku dropped to the system font. Fix: the storefront root layout loads **Noto Sans Arabic** (Google Fonts `<link>`; lazy via Arabic unicode-range — Latin-only stores never download the woff2), and `fontStack` now appends `'Noto Sans Arabic'` to every brand stack (`--bk-font-display`/`--bk-font-body`) + the tenant body cascade. A merchant's own Arabic-capable font still wins (CSS2 serves its subsets via unicode-range); this is the fallback for the Latin defaults. `app/layout.tsx`, `brand-kit-vars.ts:384`.
- **EC15 — `<html lang>` hardcoded `ar`. ✅ FIXED (Round 12, 2026-06-14).** OG `locale` now derives from the store's `default_locale` (`ogLocaleFor` → ar_IQ/en_IQ/ku_IQ) in the tenant layout + home `generateMetadata` — crawlers/social cards get the right language. `<html lang>` is corrected to the tenant locale by a client `<HtmlLang>` mounted in the tenant layout (`htmlLangFor`); the root layout still SSRs a static `ar` (it has no tenant context — a fully SSR-correct lang needs middleware→header, tracked with EC13). LTR-only: only `lang` set, never `dir`. `app/layout.tsx:28`.
- **EC16 — Delivery numbers diverge. ✅ FIXED (Round 9).** The 50K-vs-75K threshold drift across the three files is gone — all consume the shared `computeDeliveryFee` (one source of truth); see EC2. (A merchant-editable per-governorate shipping engine remains a feature grab.) `checkout_order_summary.tsx:44`, `cart_summary.tsx:44`, `checkout_form.tsx:61`.
- **EC17 — Duplicate COD orders. ✅ FIXED (Round 10, 2026-06-13).** Was: no idempotency key; lost-response retry on flaky 3G inserts a second order → a real parcel dispatched twice. Fix: `checkout_form` mints one stable `idempotency_key` per cart submission (reused across retries, cleared on success) → route schema → `submitCheckout` → `create_order_atomic`, which under its existing `create_order_lock` advisory lock returns the existing order for a repeated key instead of inserting a duplicate. Migration `20260613130000` adds the column + a partial unique index `(tenant_id, idempotency_key)` as a hard backstop (applied to NEW; live dedup verified: two calls / one order). Backward compatible — keyless orders (admin/manual/webhook) unchanged. `checkout_form.tsx:106`, `checkout.ts:195`.
- **EC18 — Custom pages render blank product grids. ✅ FIXED (Round 19, 2026-06-16).** `/p/[slug]` now fetches real products (`listProducts(tenant.id, {limit:48})`, in parallel with categories) and passes them in renderCtx instead of hardcoding `products: []` — so a product_grid on a custom page renders actual products. `p/[slug]/page.tsx:88`.
- **EC19 — Experiment data is forgeable. ✅ FIXED arm-attribution (Round 16, 2026-06-15).** Both event paths now **re-derive the visitor's arm server-side** via the deterministic `assignAbArm(experiment, visitor_key)` and ignore any client-supplied arm: `/api/exp-event` drops the client `arm_id` (re-derives), and the order route re-derives arms from the store's running experiments instead of trusting client `ab_test_arms`. An attacker can no longer pick which arm gets credit/revenue (new visitor keys get random buckets, so they can't concentrate on one arm). Revenue is the server-computed order total. REMAINING (defense-in-depth, needs a migration): a per-visitor dedup unique index to cap volume inflation of view/click events. `exp-event/route.ts`, `checkout/orders/route.ts:91`.
- **EC20 — Deleting a segment/experiment orphans variants. ✅ FIXED (Round 17, 2026-06-16).** Deleting a segment/experiment now cascade-removes variants whose `audience`/`ab_test` condition referenced it (new pure `pruneVariantsForDeletedSegment`/`…Experiment` in shared, +5 tests). Variant matching is AND so such a variant could never match again — and stripping just the dead condition is unsafe (empty conditions = "always match" → would broaden the override to everyone), so removing the whole dead variant is the correct cleanup. Scope: variants only; a section *visibility* rule referencing a deleted segment is a separate ambiguous case (left for an explicit decision). `use-store-builder-v2.ts:1021`.
- **EC21 — Scheduled changes mis-fire. ✅ FIXED the mis-fire bugs (Round 23, 2026-06-19).** (1) Timezone: the editor converted the datetime-local input with `new Date(value).toISOString()`, interpreting the wall time in the BROWSER's zone (±3h/wrong-day on a non-Baghdad browser) and ignoring the selected `timezone`. New shared `zonedWallTimeToUtcISO`/`utcISOToZonedWallTime` (Intl-based, any IANA zone) thread the SELECTED timezone through the input↔stored-UTC conversion (+7 tests). (2) Malformed `end_iso`: the resolver's `if (!Number.isNaN(end) && now > end)` left a broken-end window active FOREVER — now a malformed end makes the window not apply (+test). NOTE on the rest: a `time_window` self-fires at render once published (the resolver evaluates `ctx.now`), so the change DOES auto-activate at the scheduled time — no cron actuator needed for the change itself; "fires after publish" is by design (drafts don't touch the live store). The editor's status pills being client-computed (stale while the editor sits open) is cosmetic; a background DB-status actuator is infra (QStash/Vercel cron), out of this scope. `scheduled-changes-screen.tsx:85`, `resolver.ts:48`.
- **EC22 — Carts bleed across tenants. ✅ FIXED (Round 11, 2026-06-13).** Was: global `scheniders-cart` localStorage key; path-based `/s/a`, `/s/b` share one host → tenant B shows tenant A's items. Fix: the cart storage adapter namespaces the key by the `/s/<tenant>` path segment (`cartKeyFor`), re-derived per read/write; custom-domain stores (no `/s/` segment, host-isolated) keep the base key. `cart-store.ts`.
- **EC23 — Loose phone validation. ✅ FIXED (Round 11, 2026-06-13).** Was: server only checked `length ≥ 10`; landlines/`0000000000`/punctuation passed. - **EC24 — Stale-cart checkout dead-ends. ✅ FIXED (Round 19, 2026-06-16).** `submitCheckout` now COLLECTS per-item issues (`unavailable` / `price_changed` w/ new_price / `invalid_quantity`) instead of bailing on the first with a generic message, and returns them in the 422. The checkout form self-heals: removes unavailable lines, re-prices changed ones (new cart-store `updatePrice`), shows a specific message ("prices changed — review & confirm" / "some items removed"), and mints a fresh idempotency key so the corrected cart is a new order. Closes the silent-reprice gap too — the shopper re-confirms at the new price rather than being charged a different amount than they saw. `checkout.ts:113`, `checkout_form.tsx`, `cart-store.ts`.
- **EC25 — Preview bridge accepts any origin. ✅ FIXED (Round 16, 2026-06-15).** New `lib/preview-origin.ts` (`isAllowedParentOrigin` — hardcoded prod/dev set + `NEXT_PUBLIC_PLATFORM_ORIGIN` + localhost; `platformTargetOrigin`; `isSafePreviewNavUrl`). - **EC26 — WhatsApp handoff loses fidelity. ✅ FIXED message fidelity (Round 20, 2026-06-19).** New shared `whatsappCartLink` (items w/ variant + qty, optional delivery block, total — one source of truth) replaces the bare `wa.me/<num>` checkout-form link (now carries the whole order + the entered name/governorate/area/address) and the cart_summary inline message (also gains proper `whatsappDigits` 0→964 normalization); `whatsappOrderLink`/`WhatsappProductInfo` gained `variant`, so the PDP link now includes the chosen variant. +5 new tests (and fixed the 3 pre-existing whatsapp.test failures by using a non-placeholder number). # PART 2 — GRABS (net-new features worth stealing)

### Top 8 for Iraq COD (do these first)
1. **AI trilingual generation** — auto-translate ar↔en↔ku (batched Claude call) + per-field "write in our voice" + COD CTA presets. *The single biggest onboarding + localization unblock.*
2. **Real discount/coupon engine** — codes %/fixed-IQD/free-ship, min-cart, expiry, usage caps, phone-keyed. *The cart promo box is a dead stub; codes are the backbone of every Iraqi IG/TikTok promo.*

4. **Pixel events + Conversions API** — fire ViewContent/ATC/InitiateCheckout/Purchase (value, IQD) + Meta/TikTok server-side CAPI (COD = offline conversion). *Today only PageView fires → all ad spend optimizes blind.*
5. **Real photo reviews from delivered COD orders** — order-linked, verified-buyer, post-delivery WhatsApp request. *Biggest COD trust lever; today it can only fake them.*
6. **Bundles + order-bump + post-purchase upsell** — `product_bundle_items` already exists, unused; "add to the same COD delivery". *Cleanest AOV lever for fixed-delivery COD.*
7. **Abandoned-cart WhatsApp recovery + subscriber wiring** — capture phone early; the newsletter endpoint doesn't even exist. *Recovered revenue on the dominant channel.*
8. **Visual product picker + Arabic/Kurdish fonts** — no more UUID paste (blocks most commerce features); Arabic-capable brand fonts (fixes EC14).
