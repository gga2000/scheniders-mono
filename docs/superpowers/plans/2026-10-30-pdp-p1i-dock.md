# PDP Redesign — Slice 1i (The Espresso Dock order-button row) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ali picked concept A «الكبسولة» / The Espresso Dock (2026-10-30) for scheniders-iraq's express PDP order buttons. One espresso capsule holds, from the right in Arabic: the yellow «ثبّت طلبي» pill with an espresso arrow disc, a cream «أضف للسلة» segment and a «واتساب» segment. After an add, a cream drawer slides out from under the capsule with ✓ «انضافت للسلة · {n} بالسلة» and «شوف السلة ‹», and the cart icon carries a small count badge. The dock is opt-in (`cta_layout: "dock"`); without it every store's markup stays byte-identical. scheniders-iraq's draft gets the prop from a guarded migration applied only after the code is live.

**Architecture:** `pdp_direct_order` gains `cta_layout` (`"row" | "dock"`, optional, `.catch`-guarded). `CheckoutRow` renders `ExpressDock` in place of today's order-buttons row div when it is `"dock"`, at the same child position, so no sibling, receipt or `useId` path moves. The dock reuses everything the row has: the same submit (type, id hand-off, disabled/aria-busy/aria-describedby, label states, the `bk-xp-sheen` shine and `bk-xp-nudge` arrow), the same WhatsApp href and accessible name, and the 1g add (a `useExpressCartAdd` hook extracted verbatim from `CartTile`, so the capped add, variant hand-off, pixel parity and cart-line retirement are one code path). The confirmation drawer keeps 1g's always-present `role="status"` live region keyed by tap count. The visual details utilities cannot express (layered shadows, physical press, hairline divider, drawer slide) ship as a hoisted `<style href="bk-pdp-express-dock">` rendered only by the dock, like `ExpressMotion` ships its keyframes. A new outline `WhatsAppOutlineIcon` sits beside the filled `WhatsAppIcon`, which keeps every existing caller.

**Tech Stack:** Next.js 16 / React 19 sections package (`@scheniders/sections`), zustand, zod v4, Tailwind v3.4 (storefront), vitest 2 (node + jsdom, @testing-library/react), Supabase CLI 2.98 (`db query --linked`), PGlite 0.2.17 (local replay only, outside the repo), Playwright 1.59 (screenshots, scratch script), pnpm 10, Node 20.

## Scope decisions (read before starting)

1. **Same DOM order as today's row, LTR flex, no `dir`.** `[WhatsApp] [أضف للسلة] [ثبّت طلبي]` in DOM order paints, left to right, WhatsApp, cart, yellow — i.e. the mockup's right-to-left reading order yellow → cart → WhatsApp in Arabic. English keeps the same physical layout as today's row. Inside the yellow pill, Arabic/Kurdish put the label at the right and the disc at the left (arrow pointing left); English mirrors (arrow right).
2. **Sizes.** Capsule `min-h-16` (64px) `p-1` `rounded-[32px]` `bg-bk-secondary`, 2px gaps. Yellow pill `min-h-14` (56px) `rounded-[28px]` `flex-1 min-w-0`, padding 22px on the label side and 6px on the disc side, 44px espresso disc. Segments: WhatsApp 62px, cart **72px** (the mockup's 70px plus room for the 12px Kurdish label «خستنە سەبەتە», 66px). Every target is ≥56px tall and ≥62px wide.
3. **Labels ≥12px (mockup risk).** Segment labels move from the mockup's 11px to `text-xs` (12px) bold; the badge digit is 12px too. Labels may wrap rather than overflow (Kurdish). The yellow label is 20px/900, `min-w-0`, never truncated (no `truncate`, no `nowrap`): a long merchant label or a busy state wraps and the capsule grows (`min-h`, not `h`).
4. **360px fit.** Column 328px → yellow gets 328 − 8 − 4 − 62 − 72 = 182px; «ثبّت طلبي» at 20px/900 (~90px) + 10px gap + 44px disc + 28px padding = ~172px. No horizontal overflow (verified by measurement in Task 9).
5. **Separation from the espresso promise band below (mockup risk).** The dock wrapper adds `pb-2`, so the capsule (or the open drawer) sits 20px above the band instead of the mockup's 12px; the band's square-ish card corners against the stadium capsule keep the two shapes distinct.
6. **D4/D6.** Solid yellow (`bg-bk-primary`) only on the submit pill. The disc's arrow is `text-bk-primary` on espresso (D4 allows yellow icons on espresso). The WhatsApp glyph is a softened green (`--bk-success` mixed toward surface); the drawer's check is a success green. Only the yellow pill is `type="submit"`; the cart segment is `type="button"`, WhatsApp is a link.
7. **Behaviour preserved by construction.** The dock's submit carries the row submit's exact attributes and label states; the cart segment calls the same `useExpressCartAdd` as the 1g tile (extracted, not copied); the drawer's `<p role="status" data-cart-status>` is always present while the cart is on and its content is keyed by `note.seq`. The 1f sticky bar finds the submit by `EXPRESS_SUBMIT_ID` and the receipt by `data-receipt` — both unchanged (the receipt is outside the row).
8. **Styles.** Layout, type and token colours are Tailwind utilities. The mockup's layered shadows, press states, divider, badge ring, colour mixes and drawer motion are a `DockStyle` `<style href="bk-pdp-express-dock" precedence="bk-sections">` (React 19 hoists and dedupes it; in `renderToStaticMarkup` it lands in the preamble). Every colour there is a `--bk-*` var or a `color-mix` of two; no literal. Motion `cubic-bezier(.22,1,.36,1)` with the brand-kit durations; `prefers-reduced-motion: reduce` drops every transition and the press scale.
9. **Drawer mechanics.** Always rendered while the cart is on (so the live region exists before the first add): `grid-template-rows: 0fr`, `opacity: 0`, `pointer-events: none`, tucked under the capsule (`-mt-8 pt-8`, net zero height, inset `mx-5`, `z-0` under the capsule's `z-[1]`). `data-open` (set by the first note) animates rows to `1fr`, opacity 1, translate 0. Opacity does not remove the region from the accessibility tree.
10. **Badge.** After a tap, the bag icon shows the line's count in the cart (`note.inCart`, the number the drawer states): a cream (`bg-bk-surface`) 18px pill with an espresso digit and a 2px espresso ring, as drawn in the mockup. Never in server markup (no hydration mismatch), `aria-hidden` (the live region speaks).
11. **No new chrome strings.** The dock reuses `whatsapp`, `whatsappShort`, `addToCart`, `addedToCart`, `cartAtMax`, `viewCart` (ar/en/ku, already on the string tables and the F12/Kurdish lints) and the form's `outOfStock` / `checkingOrder` / `placingOrder`.
12. **Frozen first.** Task 1 freezes today's whole-section server markup (row off/on, ar/en/ku, sold out, no WhatsApp, variants, colour lock + band) before any code changes. Every existing baseline stays byte-identical. The only snapshot that changes is the opted-in redesign snapshot (Task 8), checked by `snapcheck.mjs`: outside the order-buttons row the only difference is the hoisted dock stylesheet in the preamble.
13. **Draft config = one key.** `pdp_direct_order.cta_layout: "dock"` on the draft only, guarded (rev 38, draft md5 `aa676deb…`, already-applied no-op, published md5 unchanged). If slice 1h's migration is applied first, the guard aborts by design: re-read and regenerate (hand-off).
