

#### [A] Direct-manipulation & canvas editing
_The canvas has the right model (click-to-select, rings, floating toolbar, inline edit, insert buttons, spacing drag) but lacks the table-stakes ergonomics of the benchmark tools. Several confirmed canvas bugs are in brokenNow (BUG1 device viewport, BUG7 picker drag, BUG16 scroll-sync, BUG17 inline-edit revert)._

- **A1** (P1·L) No canvas zoom / fit-to-width / zoom pill
    WHAT: There is no zoom control anywhere — the canvas always renders at 100% inside its container.
    WHY: A merchant can't see a full desktop composition on a laptop or zoom in to nudge details; the tablet (820px) frame silently clamps below true size with no scale indicator, so they don't know they're not seeing real dimensions.
    DO: Add Fit/50/75/100/200 + 'Fit to width' as a bottom-left canvas pill or top-bar control, applied via CSS transform:scale on the device-frame wrapper, and multiply the overlay-bounds math by the zoom factor.
    BENCH: Framer zoom pill + Cmd-scroll, Webflow zoom dropdown, Wix Studio / Builder.io Fit-to-width default.
- **A2** (P1·L) No drag-to-reorder sections on the canvas
    WHAT: Sections reorder only via the list panel or up/down buttons, not by grabbing them on the canvas.
    WHY: Grab-and-drag on the canvas is the most direct expected manipulation; without it, moving a section far is O(n) clicks or a context-switch to the rail.
    DO: Add a drag handle to the selected-section overlay (or make the ring draggable) using the existing @dnd-kit context; reuse gapRects + the insertion line, drop via the same arrayMove path as the list panel.
    BENCH: Webflow, Framer, Wix Studio, Replo all drag-reorder on-canvas with a live insertion indicator.
- **A3** (P1·M) Canvas direct-manipulation chrome is hardcoded English
    WHAT: Context-menu labels, overlay aria-labels, the pencil 'Edit' chip, inline-edit hints, spacing-handle and insert-button labels are all English literals bypassing editor-i18n.
    WHY: For a primarily Arabic/Kurdish Iraqi merchant base, the most-used editing surface ships untranslated while the rest of the chrome is trilingual.
    DO: Route all canvas chrome strings through editor-i18n STRINGS/t (add context_menu.*, inline_edit.*, spacing.*, insert.* keys). Keep layout LTR per project rule — translate copy only.
    BENCH: Shopify/Wix localize 100% of editor chrome.
- **A4** (P2·S) Clicking empty canvas does not deselect; no Escape-to-deselect
    WHAT: The canvas click handler returns early when the click isn't on a [data-section-id], leaving the current section selected; Escape only reverts an inline edit.
    WHY: Merchants expect to click away or press Escape to clear selection; the ring and toolbar persist confusingly.
    DO: Add a background-click handler that calls onSectionClick(null) when the target isn't inside a section, plus a global Escape that clears selection when not inline-editing.
    BENCH: Webflow, Framer, Figma all deselect on empty-canvas click and Escape.
- **A5** (P2·S) Context menu can render off-screen — no viewport-edge clamping or flip
    WHAT: The context menu uses raw cursor coords with a fixed min-width and 6 rows, with no measurement against viewport edges.
    WHY: Right-clicking near the right/bottom edge pushes items outside the scroll container, making them unreachable.
    DO: After mount, measure the menu rect and clamp/flip x/y to stay within the viewport, like the spacing toolbar's flip logic.
    BENCH: Radix/shadcn menus (already in this repo) and every pro builder auto-flip and collision-pad.
- **A6** (P2·M) Empty page has no rich on-canvas empty state
    WHAT: A zero-section page shows a blank white canvas with only a faint top '+'; the rich template empty-state lives in the inspector rail, not where the merchant is looking.
    WHY: First-run merchants can stare at an empty canvas not knowing where to click.
    DO: Render an on-canvas centered card ('Add your first section' / 'Start from a template') when sectionIds.length===0, reusing page-template-empty-state content wired to onAddAt(0).
    BENCH: Shopify/Wix/Framer show a prominent on-canvas add prompt on empty pages.
- **A7** (P2·M) Promo/announcement bar isn't selectable or editable from the canvas
    WHAT: The promo bar renders above the page via a separate RenderSection outside the section list, so it has no [data-section-id] participation in selection/overlay/gap systems.
    WHY: This globally-visible, high-impact element can't be directly manipulated like every other section — an inconsistent model that forces the merchant to find it elsewhere.
    DO: Make the promo bar a first-class selectable instance (stable data-section-id, tailored toolbar without up/down/delete) or show a clear hover 'edit announcement bar' affordance.
    BENCH: Shopify OS 2.0 treats the announcement bar as a clickable, editable section.
- **A8** (P2·S) sb-stage device-card chrome is defined in CSS but never applied to the preview frame
    WHAT: globals.css defines .sb-stage (layered device-card shadow, 'floats as a device card'), but the preview viewport uses a flat rounded border + weak shadow-sm; sb-stage has zero usages.
    WHY: The intended premium 'device floats on a recessed dot-grid canvas' aesthetic is half-built — the canvas reads flatter than the design system specifies, and the active breakpoint isn't communicated beyond raw width.
    DO: Apply sb-stage to the live-preview viewport; optionally add a lightweight device bezel for mobile/tablet so the breakpoint is legible at a glance.
    BENCH: Framer/Webflow/Wix Studio float the artboard with a real shadow and show device bezels.
- **A9** (P3·S) Mobile editor hardcodes the selected-section toolbar label to null ('Section')
    WHAT: mobile-editor-shell passes selectedSectionLabel={null}, so the overlay toolbar always reads the generic 'Section' instead of the real name.
    WHY: The mobile editor feels unfinished and is harder to orient than desktop, which resolves a friendly label.
    DO: Compute and pass the same friendly label derivation used on desktop.
    BENCH: Pro builders always name the selected element in the floating toolbar.
- **A10** (P3·S) Two parallel overlay implementations disagree on ring outset and clip at full-bleed edges
    WHAT: Rings are absolutely-positioned divs at -4/+8 in live-preview-overlay vs -6/+12 in preview-overlay; for full-bleed hero/promo sections the negative outset is clipped by the viewport's overflow.
    WHY: Selection rings on edge sections look cut off, and the duplicate overlay files with different outsets are a consistency smell (a side effect of the dead-vs-live duplication).
    DO: Use an inset outline/box-shadow (or clamp ring position >=0) so edge sections aren't clipped, and converge on one overlay implementation once the dead path is removed.
    BENCH: Framer/Webflow selection outlines render crisply at section edges, never clipped.


#### [B] Section library, blocks & layers
_The single registry→manifest projection driving picker/list/AutoForm is excellent zero-drift architecture, and the list panel (dnd reorder, undo-on-delete, inline-expand, presets, i18n) is strong. The two broken paths (BUG7 picker drag, BUG8 thumbnails) are in brokenNow; below are the library UX and power-merchant gaps._

- **B1** (P1·M) No copy/paste or move of sections between pages
    WHAT: Duplicate is in-page only; SectionInstance has no cross-page move and there is no section clipboard.
    WHY: A merchant who builds a great testimonials/delivery block on Home must re-add and re-fill it from scratch on Category/PDP — a daily multi-page friction point.
    DO: Add an in-memory section clipboard (Copy stashes a deep clone; Paste inserts with a fresh id) plus an optional 'Move to page…' submenu; the presets clone/instantiate plumbing already exists.
    BENCH: Webflow/Framer Cmd-C/V elements across pages; Shopify copies section settings between templates.
- **B2** (P1·M) Section library is English-only despite full bilingual data in the manifest
    WHAT: The picker hardcodes entry.name.en/description.en in five places and the list row uses manifest.name.en + an English-only SECTION_CATEGORY_LABELS, even though every section carries name.ar/description.ar.
    WHY: An Arabic/Kurdish merchant gets a fully English section library and category filter, jarring next to the fully-localized list-panel chrome.
    DO: Resolve name/description by the active editor locale (entry.name[locale] ?? .en), search across locales, and convert SECTION_CATEGORY_LABELS to a localized {en,ar,ku} lookup.
    BENCH: Shopify's section picker is fully localized including block names and category headings.
- **B3** (P2·L) No multi-select in the layers panel (bulk hide/delete/duplicate/reorder)
    WHAT: Rows are single-select with no shift/cmd handling and no selection set.
    WHY: Cleaning up a long page (hide 4 off-season promos, delete an imported block) is a one-at-a-time kebab dance.
    DO: Add shift-click range + cmd-click toggle, a contextual action bar ('3 selected · Hide · Duplicate · Delete'), and a single undoable bulk delete. Keep it pointer-driven.
    BENCH: Framer/Webflow layers panels support shift/cmd multi-select with bulk actions.
- **B4** (P2·M) No recents/favorites/smart ordering in the picker
    WHAT: The grid renders manifest entries in fixed registration order with category chips + text search only.
    WHY: A merchant who adds hero_image + product_grid on every page hunts for them in a 47-entry grid each time.
    DO: Add a 'Recently used' shelf (persist last ~6 added types per tenant in localStorage) and a pin/star to favorite sections.
    BENCH: Wix Studio, Builder.io, Plasmic surface recently-used/favorited blocks at the top.
- **B5** (P2·L) Picker preview is a tiny static thumbnail, not brand-aware or live
    WHAT: Cards show a small 16:10 static SVG (when it exists) + name + 2-line description; no hover-zoom, no larger pane, no brand-kit-aware render.
    WHY: The merchant can't tell what a section will really look like with their brand/products before adding it, raising add→undo churn.
    DO: Add a larger hover/focus preview pane; ideally a brand-kit-aware mini live render (the LivePreview infra exists) in a side detail pane.
    BENCH: Replo/Shogun render brand-aware live previews of blocks before insertion.
- **B6** (P2·S) site_header/site_footer appear as permanently-disabled cards on every page
    WHAT: Both have valid_on:[] (global chrome) but are still in the manifest, so they render greyed/'Not for this page' on all 7 pages.
    WHY: Dead clutter that pads the grid and confuses merchants ('why is Header always disabled?').
    DO: Filter manifest entries with valid_on.length===0 out of the per-page add picker (they belong on a separate Global/Header&Footer surface); sort valid sections first and collapse invalid ones.
    BENCH: Shopify separates Header/Footer/Announcement from the per-template add picker.
- **B7** (P3·S) Picker lacks result counts, per-category counts, and an empty-search reset
    WHAT: No 'Showing X of 47', no per-chip counts, and the no-results state has no 'Clear search'.
    WHY: Below the bar for a polished library; the merchant must manually clear the field and re-click 'All'.
    DO: Show a result count, add per-category counts to chips (manifest is in memory), and give the empty state a one-click reset.
    BENCH: Shopify/Webflow show counts and one-click reset in add panels.
- **B8** (P3·S) Hidden-section signal is opacity-only (color-only cue)
    WHAT: A hidden row is signaled solely by opacity-55 + an amber Eye toggle, with no 'Hidden' text badge.
    WHY: Opacity alone is weak (especially low-vision) and a 55%-opacity label can dip below contrast thresholds; the amber toggle is color-only.
    DO: Add an explicit 'Hidden' text badge alongside the dim, keeping the label contrast above 4.5:1.
    BENCH: Shopify/Webflow show an explicit 'Hidden' label, not opacity alone.
- **B9** (P3·S) Kebab row menu is hand-rolled — no focus management or viewport flipping
    WHAT: Each row's ⋯ menu is a custom absolutely-positioned div with a sibling click-scrim, fixed width, no collision/flip, no focus return — despite Radix being a dependency.
    WHY: For the last rows it clips below the panel's overflow, and it reinvents a primitive the repo already has less robustly.
    DO: Replace with the shared Radix DropdownMenu from @scheniders/ui for collision-aware positioning and focus return.
    BENCH: Every world-class builder uses a collision-aware, focus-managed menu primitive.
- **B10** (P3·M) List reorder has no live drop indicator or post-drop announcement
    WHAT: Reorder relies on default item reflow with no insertion line, unlike the canvas which draws a crisp blue drop line.
    WHY: In a dense list the drop position is ambiguous; the merchant infers it from reflow.
    DO: Draw a 2px accent insertion line in the target gap during list drag, mirroring the canvas; optionally a DragOverlay ghost.
    BENCH: Framer/Webflow layer panels draw a clear insertion line during reorder.
- **B11** (P3·XL) No section grouping/nesting — flat list only
    WHAT: SectionInstance is a flat record with no parent/children/group concept.
    WHY: Long pages (10-15+ sections) become an unscannable flat scroll with no way to collapse a logical run.
    DO: Start with a visual-only collapsible 'group label' in the layers list (no schema nesting) — high ROI for short Iraq-market pages; defer true container nesting unless merchants ask.
    BENCH: Webflow/Framer nested containers; Shopify OS 2.0 nests blocks within sections.


#### [C] Inspector / field controls / forms
_The AutoForm is an ambitious, well-architected schema-walker (recursive introspection, i18n detection, breakpoint overrides, grouping). The correctness bugs (BUG9 union, BUG18 i18n override, BUG19 empty repeater item, BUG24 no validation) are in brokenNow; below are the missing must-have controls and form polish._

- **C1** (P1·L) Repeater 'drag handle' is decorative — no real drag-and-drop reordering
    WHAT: Each array item shows a GripVertical implying drag, but reordering is only via tiny ↑/↓ buttons with no drag listeners.
    WHY: An affordance lie; reordering a 6-8 item testimonials/feature/logo list via repeated single-position clicks is slow and the 24px arrows are below comfortable touch size.
    DO: Wire real DnD on the grip using the repo's existing dnd library (the section list already reorders via DnD); keep ↑/↓ as fallback. At minimum remove the misleading grip if not wiring DnD.
    BENCH: Shopify blocks, Framer, Webflow, Replo all drag-reorder repeater items with a live drop indicator.
- **C2** (P1·M) No reset-to-default (per field or per section)
    WHAT: There's per-optional 'Clear' (sets undefined) and breakpoint 'Use base value', but nothing restores a field/section to its schema/section default — every section ships a defaultProps never exposed to the editor.
    WHY: Once a merchant breaks a layout (clears a heading, sets a bad image) there's no recovery short of retyping — a basic safety net and abandonment risk.
    DO: Thread section defaultProps into AutoForm: per-field 'Reset' (shown when current!=default) and a 'Reset section' action in the panel header.
    BENCH: Shopify 'Reset' on changed settings; Framer/Webflow 'Reset to default' on overrides; Builder.io per-field revert.
- **C3** (P1·M) .describe('video') and .describe('datetime') hints have no control; dead 'color'/'multiline' branches instead
    WHAT: StringControl branches on image/color/multiline, but the only authored hints are image, url, video (hero_video, video_block), and datetime (countdown_card); video falls to a plain text input and datetime forces hand-typing an ISO string, while color/multiline are dead code.
    WHY: Two shipped hints silently degrade — a countdown merchant hand-types ISO-8601 (guaranteed support ticket) and video has no upload/preview/validation.
    DO: Add a video branch (upload accept='video/*' + <video> preview + poster) and a datetime branch (native datetime-local reading/writing ISO); wire or delete the dead color/multiline branches.
    BENCH: Shopify video setting (upload+URL+poster); every builder uses a real date/time picker for countdowns.
- **C4** (P2·L) icon: z.string() fields render as raw text inputs — no icon picker
    WHAT: feature_grid/trust_strip items have icon: z.string() (mapped to a Material icon name), rendered as a plain text box.
    WHY: A merchant must know and hand-type exact identifiers ('local_shipping') with no list/search/preview — effectively undiscoverable, producing blank icons on typos.
    DO: Add an 'icon' hint + IconControl: a searchable visual grid popover with live previews writing the chosen identifier, showing the current glyph.
    BENCH: Webflow/Framer/Shopify icon pickers all provide a searchable visual grid.
- **C5** (P2·L) No media library / image reuse — every image is a fresh upload
    WHAT: ImageControl uploads each file to a unique tenant path or accepts a URL; there's no browser of prior tenant assets, no alt-text field, no crop/focal point.
    WHY: Reusing a logo/hero re-uploads it (duplicate storage), no alt text hurts accessibility + image SEO, and bad center-crops break mobile heroes.
    DO: Add a 'Choose from library' Media Library modal listing the tenant-assets bucket with thumbnails, plus per-image alt text and client-side crop/focal-point stored as object-position.
    BENCH: Shopify Files, Webflow Asset Manager, Framer asset panel, Wix Media Manager (focal point).
- **C6** (P2·M) No swatch picker for palette enums; native color control wired to an unused hint
    WHAT: ColorControl exists but only fires on .describe('color') which no schema uses; real color-ish fields are enums (scribble_color = butter/mint/lilac/sky/pink) rendered as plain text labels.
    WHY: A merchant picks 'Butter' with no visual of what it looks like — color-by-name with no swatch.
    DO: Render swatch chips for palette enums (resolve the token to its --bk-* color behind each option); decide whether any field should be a free color and author the hint or document color belongs in Brand Kit.
    BENCH: Framer/Webflow show color swatch + picker; Shopify color settings show a swatch.
- **C7** (P2·S) Bounded numeric fields never render a slider
    WHAT: NumberControl always renders a stepper input + a 'Range: a–b' caption, never a slider, even for clear ratios like overlay_opacity 0–1.
    WHY: Forcing decimal typing for a 0–1 opacity is clumsy and imprecise with no live 'feel'.
    DO: When both min and max exist on a continuous range, render a slider with a numeric readout; infer step from .int() vs float. Keep the stepper for unbounded numbers.
    BENCH: Framer/Webflow render opacity/bounded numerics as sliders with a readout.
- **C8** (P2·M) Repeater items show generic 'Item N' with no summary and no per-item collapse
    WHAT: Array item headers render 'Item {i+1}' with all items always expanded inline, not summarizing the item's own title.
    WHY: A 6-item testimonials/FAQ list is a very long, low-scannability rail where you can't tell items apart without reading the inputs.
    DO: Derive a smart label from the first text-ish field (title_i18n[activeLocale] truncated), make each item a collapsible card (collapsed once filled), and add a 'Duplicate item' action.
    BENCH: Shopify blocks show the heading; Framer/Webflow show a representative field and collapse by default.
- **C9** (P2·M) Long copy fields render as single-line inputs (no multiline / rich text / code editor)
    WHAT: The multiline hint is unused; paragraph i18n fields and the html_embed `html` field render in a one-line box.
    WHY: Editing body copy or HTML embeds in a ~40-char single-line box is painful and error-prone.
    DO: Detect long-text fields (key heuristic paragraphs/body/content/description, or a multiline hint) → textarea variant of I18nStringInput; render html_embed as a monospace multi-line textarea / lightweight code editor.
    BENCH: Shopify rich-text/textarea for body; Framer/Webflow multiline + code editor for embeds.
- **C10** (P2·M) No per-field help text / descriptions from the schema
    WHAT: .describe() is consumed only as a control-type switch; FieldHeader shows just an auto-humanized label, no help, no examples.
    WHY: Merchants get bare, awkward labels ('Manual Skus', 'Analytics Tag', 'Triggered After Seconds') with no explanation of purpose/format — discoverability suffers, especially in the Logic group.
    DO: Add a help-text channel (a describe convention `type|help` or a sibling meta map) rendered as muted helper text/tooltip, plus placeholders for free-form fields.
    BENCH: Shopify 2.0 settings 'info' string; Webflow/Framer field descriptions and tooltips.
- **C11** (P3·S) AutoForm's own affordance labels are hardcoded English
    WHAT: 'Set/Clear/Add/No items yet/Item N/Upload image/Unsupported field/{bp} override/Use base value' and the URL placeholder are English literals, while SectionEditPanel correctly uses t().
    WHY: An Arabic-locale merchant sees a half-translated inspector.
    DO: Route AutoForm's literal UI strings through editor-i18n STRINGS/t (add missing keys); keep layout LTR.
    BENCH: A bilingual builder localizes its own control labels, not just panel headers.
- **C12** (P3·S) Required numbers snap to 0 on clear; color hex has no normalize/validate
    WHAT: Clearing a required number writes 0 (e.g. limit=0 hides products) with no way to express 'unset'; the hex box accepts 'red'/'#gggggg' silently.
    WHY: Surprising storefront states and a specific color-validation gap on top of the broader missing validation.
    DO: Keep required-but-empty numerics flagged rather than silently zeroing; normalize/validate hex on blur (3/6-digit ±#).
    BENCH: Shopify/Framer flag required-but-empty rather than silently zeroing; every color picker normalizes hex.


#### [D] Brand kit, design tokens & theming
_buildBrandKitVars is a genuinely strong, property-tested, SSR-safe emitter (11 derived tokens from 8 colors, WCAG luminance) — above many builders. The biggest gaps are the absent preset gallery, the broken font preview, no Arabic font pairing, and an incomplete token surface._

- **D1** (P1·L) No preset / starter theme gallery — the #1 onboarding feature is absent
    WHAT: The editor has only a 'Random palette' button and one hardcoded CANDY_DEFAULTS; there is no curated full-kit theme gallery.
    WHY: A non-designer merchant can't produce a coherent palette+type+shape from 8 raw hex pickers and a random button; this is the single biggest gap vs every benchmark, which all open styling with a named theme gallery.
    DO: Ship 6-10 curated full-kit presets (colors+typography+shape+motion+voice) as a thumbnail gallery rendered via buildBrandKitVars, seeded for Iraq SMB verticals (perfume/cosmetics, fashion, electronics, grocery); store as typed Partial<BrandKit> in shared. Also feeds the empty-state.
    BENCH: Shopify OS 2.0 theme presets, Framer Styles presets, Webflow style-guide starters, Wix Studio themes.
- **D2** (P1·M) Editor font previews silently render in system fallback — merchant picks fonts blind
    WHAT: FontCombo and the typography specimen reference the selected family, but the platform document never injects the Google Fonts stylesheet (only the iframe preview loads fonts).
    WHY: Selecting 'Playfair Display'/'Anton'/'Fraunces' shows system-ui everywhere in the editor — the core value of a font picker (seeing the typeface) is broken.
    DO: On mount and on display/body change, inject a Google Fonts <link> (reuse buildBrandKitFontsUrl) into document.head; ideally render each option label in its own loaded typeface with font-display:swap.
    BENCH: Framer/Webflow render each option in its own typeface; Shopify loads theme fonts in the editor.
- **D3** (P1·L) No Arabic font pairing despite Arabic being a first-class store locale
    WHAT: BrandTypography has only display/body (single font each) over an all-Latin catalogue; there's no Arabic-capable font selection.
    WHY: Latin display fonts (Anton/Bebas/Fraunces) have no Arabic glyphs, so Arabic headlines/body fall back to an arbitrary system font with no design control — the storefront's Arabic typography is effectively unstyled in an Arabic-first market.
    DO: Add optional display_ar/body_ar (Cairo, Tajawal, IBM Plex Sans Arabic, Noto Kufi/Naskh, Almarai, Rubik), emit --bk-font-*-ar, apply via :lang(ar), with sensible auto-pairings. Content RTL inside fields is fine; app stays LTR.
    BENCH: Shopify themes and Wix support per-script font assignment.
- **D4** (P2·S) Font catalogue has broken duplicates and non-existent Google Fonts families
    WHAT: GOOGLE_FONTS lists 'Bricolage Grotesque' AND 'Bricolage', 'Playfair Display' AND 'Playfair', 'Source Serif Pro' (renamed to 'Source Serif 4'), and 'Geist'/'Geist Mono' (not served by Google Fonts CSS2).
    WHY: Selecting those builds a fonts URL Google doesn't serve, so the storefront silently falls back — the merchant picks a font that never renders live.
    DO: De-dupe and validate against the actual CSS2 API names; remove/rename invalid entries; self-host Geist via next/font if wanted; add a test asserting every entry resolves; group by Sans/Serif/Display.
    BENCH: Webflow/Framer pickers only list families they can load.
- **D5** (P2·L) No spacing / density / sizing scale token — only a 3-preset typography scale
    WHAT: The only density control is typography.scale (base font size + leading); there's no spacing scale, section-padding/gutter/container-width token, or modular type-scale ratio — whitespace is hardcoded in sections.
    WHY: Two merchants with different brand densities can't get a tight vs airy layout from the kit, and heading sizes don't relate to the base.
    DO: Add a spacing/density axis emitting --bk-space-1..6, --bk-section-padding, --bk-gutter, --bk-container-max, --bk-type-ratio; wire sections to consume them; expose Compact/Default/Roomy + container width.
    BENCH: Framer spacing tokens, Webflow spacing variables, Shopify section padding + page width.
- **D6** (P2·M) Contrast checking covers only 3 pairs; accent/surface_alt/success/danger/secondary never validated
    WHAT: ContrastBadge appears only for primary-on-surface, ink-on-surface, primary-on-ink; the SALE-sticker on-accent/accent, on-secondary/secondary, ink/surface_alt, and text over success/danger are unchecked, and there's no large-text 3:1 mode.
    WHY: A merchant can ship an unreadable pale-yellow SALE badge with white text and get no warning.
    DO: Add badges for every text-on-surface pair the renderer produces, a single aggregate 'palette accessibility: N pass/M warn', a large-text mode, and optional auto-fix suggestions.
    BENCH: Stark/Figma plugins and Shopify accessibility hints check every pairing.
- **D7** (P2·S) onColor uses a luminance threshold, not a contrast-maximizing choice
    WHAT: onColor returns #fff when luminance<0.5 else ink — a threshold, not a contrast comparison, so mid-luminance colors near 0.5 can get the worse-contrast on-color (and on-primary/primary isn't badge-checked).
    WHY: A merchant picking a mid-tone primary can get on-primary text failing AA with no signal.
    DO: Pick max(contrastRatio(color,'#fff'), contrastRatio(color,ink)) and warn if even the best is <4.5:1; hoist contrastRatio into shared so emitter and editor share one implementation.
    BENCH: Material Design and Radix Colors choose on-colors by maximizing contrast.
- **D8** (P2·M) Fixed candy mint/lilac/sky literals ignore the merchant palette
    WHAT: buildBrandKitVars hardcodes --bk-mint/lilac/sky as literals 'to keep them on-palette', and sections use them as decorative surfaces.
    WHY: A merchant who rebrands to terracotta still gets pastel mint/lilac/sky blocks clashing with their brand — three un-themeable escape hatches mean the brand kit isn't a full source of truth.
    DO: Derive mint/lilac/sky from the merchant palette (tint from secondary/accent/success or hue-rotate from secondary) or expose them as optional themeable decorative slots defaulting to the candy literals.
    BENCH: In Shopify/Framer/Webflow every section color is part of the themeable palette.
- **D9** (P2·M) Random palette overwrites all colors with no undo, ignores type/shape, and isn't contrast-validated
    WHAT: randomizePalette does a full overwrite of all 8 colors with no confirm/undo, only randomizes colors, and doesn't validate the result against AA.
    WHY: One mis-click destroys a hand-tuned palette, and the generated result is never a cohesive look (type/shape untouched) and can fail contrast.
    DO: Fold into the preset 'generate-a-theme' (complete + contrast-checked) or add an undo affordance and regenerate until primary-on-surface and ink-on-surface pass AA.
    BENCH: Hocoos/Hostinger AI builders generate complete validated themes; Framer randomize keeps undo.
- **D10** (P3·M) Color math is duplicated between editor and emitter (drift risk)
    WHAT: hex↔hsl↔rgb, luminance, contrastRatio, on-color derivation all exist twice (brand-kit-editor + brand-kit-vars) with different luminance handling.
    WHY: The editor's contrast badges and the storefront's actual derived on-colors can disagree (editor grades by WCAG ratio; emitter uses a 0.5 threshold).
    DO: Hoist the color utilities into @scheniders/shared and import in both so badge math and runtime derivation are identical.
    BENCH: Design-token tools never fork the color engine between editor and runtime.

#### [G] Save, publish, versioning & history
_The publishing core is genuinely strong (atomic advisory-locked publish RPC, real pre-publish diff, labeled 50-step undo, layered durability, non-blocking publish). The defects (BUG6 schedule, BUG21 autosave race, BUG22 diff, BUG25 conflicts, BUG27 diff_summary, BUG28 promote thrash, BUG32 status, BUG4 backup) live in brokenNow; below are the durability and history gaps._

- **G1** (P1·S) No beforeunload guard — work within the 2s autosave window is lost on close/back/refresh
    WHAT: Autosave is debounced 2s and the localStorage backup is every 30s, but there's no beforeunload handler tied to has_unpublished_changes and no router-navigation guard.
    WHY: Closing the tab, clicking back, or refreshing within ~2s (or up to 30s, given the never-restored backup) silently loses the last edits — routine on flaky Iraqi 3G where saves often sit in 'error'.
    DO: Add a beforeunload prompt when has_unpublished_changes && save_state not saved/idle, and synchronously flush a localStorage backup (and/or sendBeacon save) in the same handler.
    BENCH: Webflow/Wix/Framer/Google Docs all warn before unload with unsaved changes.
- **G2** (P1·M) Autosave failure is terminal with no auto-retry/backoff — a single flaky save strands the merchant
    WHAT: performSaveDraft sets save_state='error' and stops; recovery depends on the merchant noticing the pill and clicking Retry, or making another edit. No exponential backoff, no offline queue.
    WHY: On intermittent connectivity (the explicit reason for the PATCH fast path), a user who stops editing after a failure walks away believing nothing saved — silent data loss compounding BUG4/G1.
    DO: Auto-retry with exponential backoff (2s/5s/15s, capped) while has_unpublished_changes holds, with a 'Retrying…' pill state; keep manual Retry; treat the localStorage backup as the offline queue.
    BENCH: Google Docs/Framer/Notion auto-retry with backoff and only escalate after repeated failures.
- **G3** (P2·M) Version history caps at 50, no pagination, no compare-two-versions, no rename/delete
    WHAT: listVersions fetches 50 + named snapshots and always diffs the selected version against the current draft only; no 'compare A↔B', no rename, no delete, no 'load older'.
    WHY: After ~50 publishes early history is unreachable in the UI, and merchants can't diff two historical versions, rename a mislabeled snapshot, or prune noise — a viewer, not a real history tool.
    DO: Add cursor pagination, a second 'compare against' selector (diffJson already supports arbitrary pairs), and rename/delete actions (guarding named snapshots).
    BENCH: Webflow/Wix history offers compare-any-two, rename, and infinite scroll.
- **G4** (P2·M) Undo/redo history is in-memory only — wiped on reload, revert, and (its promise) misleads
    WHAT: past/future are useRef arrays never persisted; reload starts empty, revert_to_published clears both stacks, yet the restore dialog claims 'You can undo this in this session'.
    WHY: After any reload the merchant can't undo even one pre-reload step, and the restore-dialog promise is false post-reload.
    DO: Persist a bounded undo stack (~20 entries) to the localStorage backup so undo survives reload, fix the restore copy, and consider a server-backed 'Undo last publish' restoring the previous version row.
    BENCH: Figma/Framer persist undo across the session and survive reload.
- **G5** (P2·M) No auto-prune of unnamed auto-save versions — unbounded growth of full-config blobs
    WHAT: Every publish appends a 50-100KB full-config row forever; the migration promises pruning (named rows survive) but there is no prune job/trigger/cron.
    WHY: For multi-tenant SaaS, store_config_versions grows without bound (~365 blobs/year per daily-publishing tenant), raising storage cost and slowing created_at queries.
    DO: Add a scheduled prune (pg_cron or a QStash cron route) deleting unnamed rows older than N days or beyond the most-recent K per tenant, always preserving is_named.
    BENCH: Shopify/Webflow keep a rolling auto-version window and named restore points indefinitely.
- **G6** (P2·S) No-op republish still inserts a duplicate version row
    WHAT: publish_store_config_v2 unconditionally inserts a version row even when the diff is totalChanges===0 (reachable via publish-after-revert paths).
    WHY: Identical snapshots clutter the timeline and bloat the table; the diff already knows when nothing changed.
    DO: Short-circuit a no-op publish (clear the dirty flag, skip the RPC/insert when config equals published) and surface 'Nothing to publish — already live'.
    BENCH: Shopify/Webflow don't create a new published version when nothing changed.
- **G7** (P3·S) Restore-version dialog over-promises and gives no post-restore confirmation
    WHAT: handleRestore applies the config and closes with no success toast; the confirm copy says 'You can undo this in this session' (fragile per G4) and doesn't clarify the restored version is only a draft until published.
    WHY: A merchant may believe the restore went live immediately.
    DO: Show a post-restore toast ('Restored to <label> — now your draft. Publish to make it live.') with a one-click Publish, and make the undo copy accurate.
    BENCH: Webflow/Wix confirm a restore and make staged-vs-live explicit.
- **G8** (P3·M) Schedule creator has no overlap warning, creates empty overrides, and no quick-range presets
    WHAT: ScheduleCreatorModal validates basics but doesn't warn on overlapping windows for the same section, creates the new time_window variant with an empty {} override, and offers only raw datetime-local inputs.
    WHY: A 'scheduled' variant with an empty override renders identically to base (confusing no-visible-change), overlaps go unwarned, and manual datetime entry is error-prone.
    DO: Warn on overlapping windows for the target section, deep-link the merchant into editing the new variant's override after creation, and add quick presets (Today, This weekend, 24h, 7 days).
    BENCH: Shopify scheduling warns on overlaps and offers relative-range presets.

#### [M] Architecture, performance & reliability
_The shared resolver, atomic patch/publish RPCs, fail-soft RenderSection, and lazy-paint strategy are genuinely strong. The cross-cutting reliability defects (BUG4 backup, BUG5 boundary, BUG21 autosave race, BUG24 validation, BUG25 conflicts) are in brokenNow; below are the structural and performance items._

- **M1** (P2·M) No tenant-scope or path allowlist on the patch RPC — a member can jsonb_set arbitrary paths into any config field
    WHAT: apply_store_config_v2_patch accepts caller-controlled p_path text[] and does jsonb_set(config,p_path,p_value,true) after only verifying active membership; the route validates only the envelope shape.
    WHY: Any active member can overwrite schema_version, inject malformed pages/segments, stuff an oversized jsonb (no size cap), or create junk branches (create:true) that later fail per-section validation — the corruption entry point, gated only by 'is a member'.
    DO: Constrain p_path to an allowlist of editable top-level prefixes (pages/globals/brand_kit/segments/experiments/schedules/locales), reject schema_version/unknown roots, add a size guard, and ideally validate the resulting document against the root Zod schema/Postgres CHECK before commit.
    BENCH: Contentful/Sanity field-level APIs restrict mutations to schema-known paths and validate the result.
- **M2** (P2·L) All 47 sections are eagerly bundled via RenderSection side-effect imports — no code-splitting
    WHAT: RenderSection imports all 47 modules as side-effects to populate the registry; lazy-section.tsx defers paint, not JS.
    WHY: Every page that renders any section pulls the entire library (47 components + schemas + deps) into one client chunk on both editor and storefront — wasted JS download/parse on the Iraq 3G critical path for content-light pages.
    DO: Move to a registry of dynamic importers (registerSection with ()=>import('./hero_image') + React.lazy/next/dynamic per type), resolving needed types server-side for SSR so a page only ships the sections it instances.
    BENCH: Shopify Hydrogen and Builder.io register blocks as lazy importers and only ship a page's used blocks.
- **M3** (P2·L) Three effects JSON.stringify the entire 50-100KB config on every keystroke
    WHAT: On each config change, the history-snapshot, dirty-flag, and autosave effects each independently JSON.stringify(config), plus the 30s localStorage effect — for a content-heavy store this is the dominant per-keystroke cost.
    WHY: Every character typed serializes the whole document 3+ times synchronously on the main thread, producing visible input lag on the mid/low-end devices common in the target market.
    DO: Compute the serialized form once per change (a memo/single derived effect feeding all three), or move dirty-detection to reference equality + a structural hash via a structural-sharing store (Zustand+Immer/valtio), stringifying only at the save boundary.
    BENCH: Framer/Webflow keep per-keystroke work O(changed-node) via immutable structural sharing.
- **M4** (P2·XL) State is a 1123-line hand-rolled hook coordinating ~10 mutable refs — fragile, hard to test, no single source of truth
    WHAT: useStoreBuilderV2 holds config in useState but undo/redo/save in skipHistoryRef/lastSnapshotRef/pending refs + a historyTick counter (with eslint-disable on can_undo/can_redo deps), and imports a banned module-level supabase client.
    WHY: Undo correctness depends on fragile imperative ref-coordination (the segment-CRUD bypass and tick hack are symptoms), can_undo/can_redo are derived from refs React can't see, and there's no command log to enable server-authoritative history or future multiplayer.
    DO: Extract config+history into a command-based store (Zustand reducer or useReducer history middleware) with a typed undo stack, plain derived can_undo/can_redo (no tick/eslint-disable), and described section/segment/experiment commands; switch to the mandated lazy supabase getter.
    BENCH: Framer/Plasmic/tldraw model editor state as a command/transaction store with a typed undo stack.
- **M5** (P3·M) Live-preview page switch always does a full iframe reload (white flash, lost scroll), no warm cache
    WHAT: Page navigation does a full iframe location.replace re-fetching all server data and re-establishing the bridge, even when the target page's server data is unchanged or already-cached.
    WHY: A merchant flipping between Home/Category/Product to compare gets a full white-flash reload each time, losing scroll and the bridge 'ready' state.
    DO: Keep visited preview pages warm (an iframe per recently-visited page, or in-memory page-map switch when only page_id changes), preserve scroll, show a skeleton instead of white, and only hard-reload when product_id/category_id actually change.
    BENCH: Webflow/Framer keep the canvas warm and switch pages in-place; Shopify preserves preview scroll.


#### [N] Net-new world-class capabilities (the big gaps)
_Capabilities that are entirely absent and that a serious merchant hits within the first week — these are the strategic swings that move the builder toward the benchmark beyond fixing what exists._

- **N1** (P1·M) No custom-code / pixel injection, and stored custom_css has no editor UI
    WHAT: Confirmed: custom_css exists on StoreConfigV2 and is injected into the storefront <head>, but has zero editor references in store-builder-v2; there's no head/body script injection and no first-class Meta/TikTok/Google pixel fields (only the per-section sandboxed html_embed).
    WHY: For an Iraq store running paid social, missing pixel injection directly breaks ad attribution and retargeting — launch-critical for paid acquisition — and the half-wired custom_css is a dead, invisible capability.
    DO: Add a 'Code & tracking' settings screen: a custom_css editor (lightweight CodeMirror), head/body script fields with warnings, and first-class Meta Pixel ID / TikTok Pixel ID / Google tag fields rendering the official snippets server-side.
    BENCH: Shopify (custom CSS + Additional scripts/web pixels), Webflow head/footer code, Wix tracking & analytics, Framer custom code.
- **N2** (P2·L) No AI copy/section generation anywhere in the builder
    WHAT: AI exists only for customer summaries; nothing in the builder generates or rewrites content, and the brand_kit.voice field (formality/notes) is never used.
    WHY: AI generation is the headline feature of every modern builder, and the highest-value version here is bilingual — generate Arabic+English headline/subhead/CTA/blurbs in the brand voice and auto-translate one locale to the other (directly relieving the I1 hand-translation burden).
    DO: Add inline 'Generate with AI' on text/i18n fields and 'Draft this section' in the picker, producing bilingual copy from brand_kit identity+voice+context; add 'Translate to AR/EN' in the i18n screen; reuse the customer ai-summary server plumbing, human-in-the-loop.
    BENCH: Shopify Magic, Wix AI, Framer AI, Hostinger/Hocoos AI builders, Builder.io Visual AI.
- **N3** (P2·M) No URL redirects manager — broken-link / SEO recovery is impossible
    WHAT: There is no redirects model in StoreConfigV2 and no UI, yet product/category slugs (and future custom-page URLs) can change.
    WHY: When a slug changes, old inbound links — ad links, WhatsApp-shared links, indexed Google results — 404, losing SEO equity and dead-linking exactly the WhatsApp/social distribution this market relies on.
    DO: Add redirects: {from,to,status}[] to StoreConfigV2 with a management screen (validate loops/conflicts) honored in storefront middleware; optionally auto-suggest a redirect on slug change.
    BENCH: Shopify URL Redirects, Webflow 301s, Wix redirect manager, Framer redirects.
- **N4** (P2·L) No whole-store starter themes / template marketplace
    WHAT: page-templates are per-page only; there's no StoreTheme that sets brand_kit + all pages + globals together, and no gallery/marketplace.
    WHY: A new Iraq merchant wants to pick a complete look ('Perfume editorial', 'Electronics') and have colors+fonts+every page populated in one click — the 'instant beautiful store' first-run moment top builders lead with.
    DO: Add whole-store StoreTheme presets (brand_kit + every page + globals) surfaced as a gallery in onboarding and an 'Apply theme' action with a replace-confirm; curate 4-6 vertical Iraq themes. (Pairs with D1.)
    BENCH: Shopify Theme Store, Webflow/Framer marketplaces, Wix templates, Replo page library.
- **N5** (P3·XL) No content collections / metaobjects (and no blog)
    WHAT: Repeatable content (testimonials, branches, FAQs) is typed inline per-section instance; there's no reusable collection/metaobject layer and no blog/article model.
    WHY: Editing the same testimonials/branches/FAQs across pages means re-entering and drift, and the absence of a blog caps content-driven organic SEO.
    DO: Add a lightweight collections layer (named lists of typed records, bindable by sections via a reference instead of inline arrays), starting with a blog/article collection + a list/show section. Sequence after custom pages (E4) and media library (C5).
    BENCH: Shopify Metaobjects, Webflow CMS Collections, Framer CMS, Wix Content Manager.
- **N6** (P3·L) No general form builder beyond newsletter/checkout, and no submissions inbox
    WHAT: Forms are fixed-purpose (newsletter email, COD checkout); there's no configurable lead/contact/pre-order/back-in-stock form and no submissions view.
    WHY: COD merchants frequently need a custom lead capture (phone + WhatsApp opt-in is the real lead) or wholesale-inquiry form; today those leads are lost or pushed off-platform.
    DO: Add a form-builder section (configurable fields incl. governorate select + WhatsApp opt-in), a submit action (store + optional WhatsApp deep-link/notify), and a submissions list, reusing the governorate select and phone-normalization utils.
    BENCH: Webflow Forms, Wix Forms, Shopify contact form + apps, Framer forms.
- **N7** (P3·XL) No real-time collaboration, presence, or in-context comments
    WHAT: The editor is single-user with no presence/lock and no per-section comments; combined with no conflict detection (BUG25) two people clobber the shared draft.
    WHY: Merchants increasingly work with an agency/marketer; without presence or comments concurrent editing collides and there's no way to leave in-context feedback.
    DO: Start with a soft edit-lock + presence indicator via a Supabase realtime channel and per-section comment threads keyed by (page_id, section_id); defer full multiplayer co-editing.
    BENCH: Framer/Figma multiplayer + comments, Webflow comments + locks, Builder.io comments.
- **N8** (P3·L) No per-section animation / scroll-interaction controls
    WHAT: Motion is a single global brand_kit.motion {enabled,speed} + broad CSS scroll-reveal; no inspector control to choose a per-section entrance/scroll/hover effect.
    WHY: Brand-defining storefronts use selective motion (parallax hero, count-up stat strip); all-or-nothing global motion is a differentiation gap.
    DO: Add an optional per-section motion block (entrance none/fade/rise/zoom, trigger on-load/on-scroll, intensity) as an inspector group layered over the global default, CSS-driven and honoring prefers-reduced-motion.
    BENCH: Framer interactions, Webflow Interactions, Wix Studio animations, Replo per-component animation.


#### [O] Visual polish & micro-interactions
_The 'Elevated Light Glass' chrome is genuinely refined (save-state pill, publish ping, scroll-sync, tinted tiles, reduced-motion respect). The remaining polish gaps concentrate in the top bar, the IA of power screens, and a few honesty/labeling issues._

- **O1** (P1·M) Top bar is a single non-responsive flex row — overcrowds/clips below ~1280px and jitters on save-state change
    WHAT: The header packs ~10 controls (locale, breakpoint, undo/redo, preview-as, i18n pill, Open, save pill, Publish) in a flex row with no min-w-0, overflow menu, or breakpoint hiding, and width-variable pills ('Saved 12m ago', 'ar 100% / en 100%') reflow as state changes.
    WHY: On a common 1366px laptop with both rails open, the row crowds/clips and the layout jitters as autosave ticks.
    DO: Make the bar responsive: collapse secondary controls into a 'More' overflow below a width threshold, give the middle group min-w-0, and reduce variable pills to icon-only under ~1280px; test at 1280/1366/1440.
    BENCH: Framer/Webflow keep the top bar to ~3 stable zones with secondary controls in menus; none let width jitter on save.
- **O2** (P1·L) Power screens replace the whole canvas with no breadcrumb, active-state, or exit affordance
    WHAT: Brand Kit/Versions/Scheduled/Segments/Experiments/i18n swap the entire main for a full-screen panel (hiding canvas + inspector) with no active-state on the page-tree settings buttons and no top-bar breadcrumb/back-to-canvas — exit depends on each screen's own close, while inert toolbar controls (breakpoint, preview-as) still show.
    WHY: The merchant is teleported with no 'you are here' affordance and can feel trapped, unlike the Health tab which was correctly moved inline.
    DO: Add active-state styling to the settings buttons, a top-bar breadcrumb + persistent Close when a system_screen is open, dim the inert canvas-only controls, and consider hosting these as right-docked panels (Framer/Webflow pattern) rather than full takeovers.
    BENCH: Webflow/Framer open version/CMS/audience as panels keeping the design visible with the nav highlighting the active section.
- **O3** (P2·M) Flagship advanced screens are double-buried in a collapsed, unlabeled 'Advanced' accordion with no activity badges
    WHAT: Audiences, A/B tests, Scheduled changes, and Past versions live in an ADVANCED_SETTINGS accordion that defaults closed (localStorage-persisted) at the bottom of the page rail, with no count/badge for live activity.
    WHY: A merchant who never expands it never discovers A/B testing or scheduled publishing — four of the builder's most differentiating capabilities are hidden behind a generic collapsed label.
    DO: Add live-state badges (e.g. '2 experiments running', '1 scheduled change', unpublished-diff dot) on the Advanced toggle/items, promote Versions + Scheduled to primary (they're operational), and default the accordion open on first visit.
    BENCH: Wix Studio/Builder.io put experiments/versions in the primary toolbar with activity badges.
- **O4** (P3·M) Mobile editor buries breakpoint/locale/preview-as/undo-redo behind an unlabeled '...' with an inert device toggle
    WHAT: Four capabilities live behind the mobile top-bar More button; undo/redo is two taps deep, and the breakpoint toggle in the drawer does nothing because the mobile canvas is locked to mobile.
    WHY: Hard-to-discover controls, frequent undo buried deep on a phone (where errant edits are likelier), and a device toggle that visibly does nothing is misleading.
    DO: Promote undo/redo to the mobile top bar, hide the inert breakpoint toggle on the phone shell (or honor it), and label/split the More button.
    BENCH: Shopify/Wix mobile editors keep undo/redo and device toggle first-class and never show a no-op device toggle.
- **O5** (P3·S) Top-bar locale select reads as a global language switch but only changes preview locale
    WHAT: A bare Globe ar/en dropdown (aria-label 'Preview locale' but no visible 'Preview' qualifier) sits in the chrome and drives set_active_locale, conflated with breakpoint.
    WHY: Merchants may think selecting 'en' changes their store's default language or enabled locales (actually managed in the i18n screen) — an IA ambiguity.
    DO: Group the locale select inside the same 'preview context' cluster as breakpoint/preview-as and add a small 'Preview' qualifier/eye icon, keeping the i18n coverage pill visually distinct.
    BENCH: Webflow/Shopify clearly separate 'simulate in locale X' from 'site languages' settings.
